# ADR-0001 用 Go 重写，而不是 Rust

- 状态：已接受
- 日期：2026-10-18

## 背景

新项目要从零开始做 TUI，语言可选 Go 或 Rust。候选评估基于两点：能搬多少 v1 的东西，以及音频链路的风险。

## 决策

用 Go。

## 理由

1. **领域层可搬迁**：v1 有 8,189 行非测试 Go 代码 + 2,668 行测试，包含多 P 命名、收藏夹同步、歌词匹配、netguard 等大量已踩过的坑。
2. **网易云客户端有现成 Go 库**：`go-musicfox/netease-music` 约 203 个文件、160+ API，含 weapi/eapi 加密、二维码/手机号/邮箱登录、`song_url_v1` 八档音质。Rust 侧需要自己移植加密与端点，并长期跟接口变化。
3. **Rust 的音频优势没有想象中大**：`symphonia` 的 AAC-LC 状态是 *Great*，但 HE-AAC / HE-AACv2 完全未实现；与 Go 的 `go-aac` 面对同一个缺口。最终两边都要给 HE-AAC / EC-3 留外部解码兜底（见 ADR-0003）。
4. **Bubble Tea 的形态贴合这个应用**：表单、列表、弹窗密集，Elm 架构 + `tea.Cmd` 正好把音频与网络事件挡在主循环之外。

## 后果

- 需要 Go 1.26+（`charm.land/*` v2 与 `oto/v3` 的要求），本地工具链要升级。
- 若将来改主意换 Rust，`internal/domain` 与 `source.Source` 契约可以照搬，接口设计是语言无关的。

## 替代方案

Rust + ratatui：UI 与音频库更强、类型系统更严，但领域层与网易云客户端全重写，首版工期约 ×1.4–1.6。仅当 Rust 是长期主力语言时值得。

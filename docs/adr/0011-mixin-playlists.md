# 0011 混合歌单：引用而不是复制

状态：已接受

## 背景

用户希望在保留远端歌单自动同步的同时，在当前歌单里追加自己的曲目，并且不改动源歌单；
同一个歌单还可能同时引用多个来源。Half-Beat 的「锁定/解锁」解决的是单个同步歌单转本地，
但不覆盖多歌单组合。

## 决策

新增 `kind = mixin` 的混合歌单：

- `playlist_refs` 保存引用歌单及顺序；引用不能是另一个混合歌单。
- 自己的曲目仍写 `playlist_items`。
- 删除继承曲目写 `playlist_excludes`，不修改源歌单。
- 有效曲目 = 按引用顺序去重后的源曲目 + 自己的曲目，再减去 excludes。
- 打开混合歌单时刷新其中的远端引用。
- 同步歌单可「解锁」为本地歌单：保留 ID 和全部曲目，清空 source/remote_id。

## 理由

- 引用而不是复制，源歌单变化可以自动反映。
- exclusion 让删除只影响当前歌单，符合「原歌单不受影响」。
- 不嵌套可以避免循环引用和递归展开的复杂度。

## 后果

- 必须处理引用删除保护：被引用的歌单不能直接删除。
- 混合歌单的曲目数是实时计算的，`ListPlaylists` 需要额外展开。
- 解锁不可逆，但符合 Half-Beat 的用户预期。

## 替代方案

- 物化复制源曲目：实现简单，但源歌单更新后无法自动同步。
- 允许嵌套：更灵活，但需要环检测和更复杂的删除语义，暂不做。

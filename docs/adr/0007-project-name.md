# ADR-0007 项目命名：zero-beat / zero

- 状态：已接受（2026-10-18）
- 取代：先前「暂用占位名、定名后再改」的提议

## 背景

需要一个同时满足四件事的名字：能当 Go module 与仓库名（可带连字符）、能当二进制名（要好打）、和 v1「半拍 / Half Beat」有延续关系、中文能念出意思。

## 决策

| 项 | 值 |
| --- | --- |
| 仓库 / 包名 / slug | `zero-beat` |
| 二进制 / 命令 | `zero` |
| Go module | `github.com/sheyiyuan/zero-beat` |
| 中文名 | 零拍 |

包名与二进制名分离是有意的：仓库要可搜索、可 SEO，命令要短。

## 理由

1. **家族延续**：`half-beat`（半拍，桌面版）→ `zero-beat`（零拍，TUI 版），保留 `-beat` 后缀，一眼看出是同一产品线。
2. **术语本身说得通**：zero beat 是无线电里的真实概念——两个振荡器频率完全相同时，差拍归零，听不出拍频。这正是多源播放器要做的事：两个平台的同一首歌同频，切源时听不出接缝。卖点句可以直接写「差拍归零，切源无缝」。
3. **命令够短**：`zero play BV1xx` 四个字符，比 `onbeat`、`halfnote` 都好打；AUR 上的 `zero` 与 `zero-bin` 均未被占用。

## 已知代价

1. **同类项目已有同名**：`Finsiii/ZeroBeat-CLI` 是一个终端音乐播放器（1 星，基本停滞）。同名同赛道会互相干扰搜索结果，属于可接受但需要知道的代价。
2. **`zero` 太通用**：GitHub 上 `zero` 相关项目海量，用户很难靠搜索找到本项目，只能靠 README 与包名区分。缓解：README 首句就把 zero beat 的技术含义讲清楚。
3. **Go 代码里 grep 噪音**：`zero` 是 Go 的常用词（zero value、zero-length），在代码与文档里搜 `zero` 会混入大量无关结果。缓解：命令名在文档中统一用反引号包裹，代码里不出现 `zero` 作为变量名。

## 后果

- 二进制名与仓库名不同，发布时 AUR 包名用 `zero-beat` / `zero-beat-bin`，命令仍是 `zero`。
- 中文名「零拍」的推广需要解释成本，README 与发布说明里要带上那句话，否则容易被读成「没拍子」。

# 0012 可配置快捷键：动作 ID + TOML 覆盖

状态：已接受

## 背景

快捷键已经覆盖播放、列表、歌单、登录和混合歌单。继续把 `isKey("n")` 散落在
handler 里，既不能自定义，也很容易在改键时漏掉某一条路径。

## 决策

- 引入稳定的动作 ID（`next`、`play_pause`、`login_image`…），所有 handler 只匹配动作。
- 内置默认绑定；`~/.config/zero-beat/keymap.toml` 按动作覆盖，未写出的动作沿用默认。
- 只支持单键/命名键，不支持多键序列。
- 文本输入、`enter`/`esc`、`Tab`、`1–6` 固定。
- 启动时校验未知动作、非法按键和重复绑定；任何错误回退默认并提示。
- `H` 弹窗、底部提示和右上角账号提示读取实际绑定。
- 提供 `zero keymap --init` 生成完整示例，`--check` 做无 TUI 校验。

## 理由

- 动作 ID 把配置和实现解耦，改键不影响功能路径。
- 整份配置冲突时回退，避免「一个键触发两个动作」的隐蔽误触。
- 登录图片改为 `o`，退出登录用 `ctrl+w`；旧 `v`/`W`/`X` 仍兼容。

## 后果

- 每次 UI 渲染/按键匹配都要通过 Keymap，而非硬编码字符串。
- 自定义键位过长时帮助页会截断，但 `H` 弹窗仍可滚动查看。

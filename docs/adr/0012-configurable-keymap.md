# 0012 可配置快捷键：动作 ID + TOML 覆盖

状态：已接受（2026-10-22 修订冲突策略与歌词键，见文末）

## 背景

快捷键已经覆盖播放、列表、歌单、登录和混合歌单。继续把 `isKey("n")` 散落在
handler 里，既不能自定义，也很容易在改键时漏掉某一条路径。

## 决策

- 引入稳定的动作 ID（`next`、`play_pause`、`login_image`…），所有 handler 只匹配动作。
- 内置默认绑定；`~/.config/zero-beat/keymap.toml` 按动作覆盖，未写出的动作沿用默认。
- 只支持单键/命名键，不支持多键序列。
- 文本输入、`enter`/`esc`、`Tab`、`1–6` 固定。
- 启动时校验未知动作、非法按键和重复绑定；任何错误回退默认并提示。
- `H` 弹窗、底部提示和右上角账号提示读取实际绑定。
- 提供 `zero keymap --init` 生成完整示例，`--check` 做无 TUI 校验。

## 理由

- 动作 ID 把配置和实现解耦，改键不影响功能路径。
- 整份配置冲突时回退，避免「一个键触发两个动作」的隐蔽误触。
- 登录图片改为 `o`，退出登录用 `ctrl+w`；旧 `v`/`W`/`X` 仍兼容。

## 后果

- 每次 UI 渲染/按键匹配都要通过 Keymap，而非硬编码字符串。
- 自定义键位过长时帮助页会截断，但 `H` 弹窗仍可滚动查看。

## 修订（2026-10-22）

v0.5 把 `j` / `k` / `h` / `l` 恢复为默认方向键与左右焦点（vim 习惯），歌词页
因此改用单键 `T`（页面键沿用 `F`/`L`/`H`/`N` 的大写惯例），`ctrl+l` 作为备选绑定
保留。没有采用「单按 Ctrl」：终端默认不发送裸修饰键，只有开启 kitty 键盘协议的
终端才会上报 `KeyLeftCtrl`，且开启后 Ctrl+C/D/W 等组合会先触发一次裸 Ctrl，
用释放事件绕开的复杂度与出错面都不值当。

同时修订冲突策略：原规则「任何一个键撞车就整份配置回退默认」会把用户的自定义
全部静默丢掉（例如旧配置把 `logout` 绑在 `W`，撞上后来新增的默认
`download_selected = W`，就会整份失效）。新规则：

- 用户显式写出的动作优先；与它冲突的**默认**绑定被移除，并在启动时用黄色提示
  说明哪个默认动作让位，其余配置照常生效（`Load` 改为返回 warnings 的
  `LoadWithWarnings`，TUI 显示提示，`zero keymap --check` 打印提示）。
- 只有两个**都是用户自定义**的动作抢同一个键时才整份拒绝并回退默认，避免
  一键双触发的隐蔽误触。
- `build` 处理顺序按「先用户覆盖、再按动作名排序」固定，保证同一份配置每次
  得到相同的绑定与提示（原实现依赖 map 遍历顺序）。

结果：旧版 `--init` 产物无需改动即可加载；`zero keymap --check` 能给出可操作
的迁移提示。

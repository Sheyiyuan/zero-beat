# 0013 播放片段、云端歌单写入与引用混入

- 状态：已接受
- 日期：2026-10-21

## 背景

用户需要三件相关能力：

1. 给一首歌设播放区间，只听其中的片段；
2. 把当前播放/选中的歌加入歌单，包括同源的云端歌单；
3. 把当前选中的歌单混入另一个歌单。

原有实现里，`a` 只能加入程序隐式选中的本地/混合歌单；混合歌单只能通过 `N`
新建或 `M` 编辑引用；云端歌单完全只读。播放区间则没有任何数据或引擎支持。

## 决策

### 播放片段

- 区间按歌曲存在 `settings` 的 `clip:<songID>`，格式
  `{"start_ms":...,"end_ms":...}`；`end_ms == 0` 表示到结尾。
- 不写入 `songs` 表：区间是本地偏好，和 `lyric_offset:<songID>` 同一生命周期，
  远端歌单刷新/`UpsertSong` 不会覆盖它。
- `audio.Stream` 增加 `ClipStartMS` / `ClipEndMS`；引擎用 `-ss` + `-t` 把解码限制在区间内。
- **播放位置和时长保持全曲绝对时间**，不做区间相对时间。歌词、断点恢复、队列进度
  都依赖绝对时间；进度条只把区间外画暗，并显示 `✂` 标签。
- 区间编辑是模态浮层，不新增 `view`：`C` 打开，`{` / `}` 在当前位置设起止，
  `ctrl+r` 清除，`enter` 保存并从起点重播，`esc` 取消。
- 编辑过程中第一次把光标移出旧区间时，临时把引擎切到「整首预览」，否则旧区间的
  `-t` 会把光标锁在旧范围内；保存/取消时再用新区间或原区间恢复。`start_ms == 0`
  表示原曲开头，`end_ms == 0` 表示原曲结尾；在结尾按 `}` 会存回 0 哨兵。

### 云端歌单写入

- `source` 增加可选能力 `CapPlaylistWrite` 与 `PlaylistWriter`:
  `AddToPlaylist(ctx, remoteID, ref) error`。
- 不把方法加进 `source.Source` 主接口：保持第三方/测试实现不被强制扩展，UI 按能力位检测。
- B 站：把收藏夹写入 `/x/v3/fav/resource/deal`；需要 `aid` 和 cookie 里的 `bili_jct`。
- 网易云：走 weapi `/api/playlist/manipulate/tracks`（`op=add` + `pid` + `trackIds`）；旧 `/api/playlist/track/add` 在部分账号会返回 401。
- 目标歌单必须和歌曲同源；远端列表在打开目标选择器时异步拉取，不自动导入曲库。
  已导入的镜像在写入成功后按需刷新；未导入的只提示写入成功。

### 歌单混入

- 「混入」一律是**引用**，不复制曲目：目标必须是 `kind = mixin`，源必须不是混合歌单
  （沿用 ADR-0011 的不嵌套约束）。
- 新增 `Store.AddMixinRef`，幂等追加，UI 入口是 `S`。
- 不做「本地歌单合并」或「复制曲目」：需要复制时，用混合歌单引用源即可。

## 理由

1. 区间是本地播放偏好，存 `settings` 避免改 songs 的建表、迁移和重复 INSERT。
2. 绝对时间轴改动最小，不会让歌词和第二天的断点恢复错位。
3. 云端写入是可选能力，B 站/网易云协议差异留在各自包内，TUI 不写平台分支。
4. 「混入 = 引用」与现有混合歌单模型一致，源歌单更新自动同步，也不会产生跨平台重复副本。

## 后果

- ffmpeg 的 `-t` 在约 100ms 的输出缓冲内可能多放一点尾音；需要采样级精确时只能走导出路径，
  当前明确不做导出。
- 云端写入只支持加歌，不支持删除、改名、取消收藏或完整分页；网易云通常只能写自己创建的歌单。
- 目标选择器需要异步拉云端列表；打开时先显示本地/混合目标，云端列表到达后追加。
- 混合歌单不能引用另一个混合歌单；要组合多个混合歌单，只能分别引用它们的源歌单。

## 替代方案

- 区间存 songs 列：列表页查询方便，但要改迁移和多处 INSERT，且远端刷新有覆盖风险。
- 引擎外 tick 判断终点：实现快，但精度差、seek 越界难处理。
- 直接把 `AddToPlaylist` 加进 `Source`：接口更直观，但会强制所有音源和测试桩实现一个并非都支持的能力。
- 混入时复制曲目：可写进本地歌单，但失去源同步，且与 ADR-0011 的引用模型冲突。

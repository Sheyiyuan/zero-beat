# ADR-0006 搬迁而不是重写：领域层与测试成建制搬过来

- 状态：推迟（v0.1 是重写的最小闭环，v1 搬迁与数据导入器见 ROADMAP）
- 日期：2026-10-18

## 决策

1. 新仓库独立，但 `internal/{models,db,lyrics,netguard,services}` 以搬迁改造的方式进来，不做「重新想一遍业务」。
2. v1 仓库冻结，只修 bug。
3. 提供 v1 数据库导入器，导入幂等、支持 `--dry-run`、导入前自动备份。

## 理由

1. v1 的业务逻辑已经覆盖了大量边界：多 P 命名、收藏夹分页与双向同步、歌词多源匹配、SSRF 防护、音频 URL 过期刷新。重写这些是纯损失。
2. 2,668 行测试跟着搬，就是重构的回归网。
3. 老用户的歌单不能丢——这是重写最容易得罪人的地方，也是必须显式提供导入器的原因。

## 后果

- 迁移期间两个仓库并存，v1 的新 bug 修复需要判断是否需要同步到新项目（预期很少，v1 冻结）。
- 搬迁时要顺手修掉已知问题（选轨取 `audio[0]`、直链落库、凭证明文），不能原样复制。

## 替代方案

完全重写：代码可能更干净，但会把两年的边界经验重新踩一遍，且用户数据迁移依然要写。

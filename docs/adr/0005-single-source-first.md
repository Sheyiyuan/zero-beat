# ADR-0005 先单源落地，接口按多源设计，能力位驱动 UI

- 状态：已接受
- 日期：2026-10-18

## 决策

1. 第一阶段只实现 B 站音源，但数据模型、`Source` 接口、UI 逻辑全部按多源设计。
2. UI 依据 `Capability` 位决定控件显隐，代码里不出现 `if source == "bilibili"`。

## 理由

1. 一次上两个平台，会在抽象还没被验证时同时引入两种平台特性（多 P、收藏夹、音质档位、歌词来源），很容易把抽象写成平台分支的集合。
2. 单源先行 4–6 周就有可用产品，再把网易云作为第二个实现加进来（约 3–4 周），总工期几乎不变，但风险分布完全不同。
3. 能力位是"多源"真正的落地形式：新平台的差异体现在能力声明上，而不是散落在 UI 里的条件判断。

## 后果

- `Capability` 的初始集合（搜索、分 P、远端同步、官方歌词、音质选择）必须一次想清楚，后续只能加不能滥用。
- B 站实现里平台特有的概念（BV 号、分 P）必须收在 `source/bilibili` 内部，通过 `extra` 透出，不能污染 `domain`。

## 替代方案

一步到位双源：看起来快，实际上会在抽象未定型时返工两次。

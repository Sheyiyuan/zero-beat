# 跨设备同步

歌单、混合歌单、快捷键配置、单曲歌词偏移 / 歌词绑定 / 单曲音量补偿 / 片段，以及加密后的登录态，都可以同步到你自己的 git 仓库（GitHub 私有仓库、Gitea、自建裸仓库都行）。仓库需要自己先创建。

本地文件夹歌单、仅本机歌单、本地曲目上的注释与本地歌词绑定**不会**进入仓库：它们跟设备与文件路径绑定，换设备无法复现。

## CLI

```bash
zero sync init --remote git@github.com:me/zero-beat-sync.git --branch main
zero sync status
zero sync pull          # 拉取、合并、导入
zero sync push          # 导出、提交、合并、推送
zero sync conflicts     # 查看冲突实体
zero sync resolve <tx> --all local|remote
zero sync key rotate    # 换口令并重加密登录态
```

`zero sync` 可以查看全部子命令。

## 同步页

TUI 里按 `ctrl+s` 打开同步页，也可以点右下角的同步状态。页面包含状态、仓库与分支、连接方式（SSH/HTTPS）、密钥、自动同步、冲突入口和归档目录。

| 操作 | 说明 |
| --- | --- |
| `↑` / `↓` + `enter` | 选择操作；在仓库地址、分支、口令、令牌行上直接打字即可编辑（不必先按 enter） |
| `space` | 勾选「歌单会以明文托管」；未勾选时不能初始化 |
| `连接方式` | 在 SSH 与 HTTPS 之间切换；切换后密钥与登录态依然有效 |
| 同步口令 | 至少 12 个字符，输入不回显；确认后行内显示「已输入」 |
| 粘贴 | 编辑仓库地址、口令、令牌时使用终端粘贴（`ctrl+shift+v`、`cmd+v` 或中键） |

首次初始化必须勾选「歌单会以明文托管」；同步口令不回显，只在本机内存里短暂停留，提交后立即清除。

## 冲突页

| 操作 | 说明 |
| --- | --- |
| `l` / `r` / `b` | 逐项保留本地 / 远程 / 两者（两者仅歌单） |
| `L` / `R` | 全部本地 / 全部远程 |
| `enter` | 全部选择后应用、提交并推送 |
| `esc` | 返回同步页 |

落选版本归档到 `~/.config/zero-beat/sync/archive/`，不会丢。

## 仅本机数据

同步只处理「用户显式选择 + 跨设备可复现」的数据。下面这些只在本机存在：

| 数据 | 为什么不同步 |
| --- | --- |
| 文件夹歌单（`[夹]`） | 内容是磁盘路径，别的设备不一定有同一个目录 |
| 仅本机歌单（`[仅]`） | 显式标记 `sync_excluded=1`，创建时就决定不进仓库 |
| 引用文件夹 / 仅本机歌单的混合歌单 | 引用目标不在仓库里，过去会断 |
| 本地曲目本身与其注释 | 曲目身份来自本机文件 |
| 本地歌词绑定（`local_file` / `local_song`） | 指向本机文件或本机曲目 |

同步页会显示「仅本机 N 个歌单 · 本机注释 M 条」，避免误以为换设备丢数据。导入（包括 `KeepLocal=false`）也不会删除这些数据。

平台歌曲上的 portable 歌词绑定（网易云 / LRCLIB）会随注释同步；平台歌曲上的本地歌词绑定不会。

## 仓库格式 v2

v0.7.0 起同步仓库格式为 `meta.v=2`，新增「仅本机」边界与歌词绑定字段：

- 新客户端能读 v1 仓库，并在首次成功同步后**原地升级**为 v2，同步页会提示「仓库已升级到 v2，旧版本客户端将无法同步」。
- 升级不可回退。旧客户端读到 v2 会要求升级，而不是带着不认识的字段继续导出。
- **多设备用户请先升级所有设备**，再让任意一台执行同步。旧客户端参与同一仓库可能把仅本机歌单重新导出，或在导入时删掉它们。

## 连接方式

- `git@host:...` / `ssh://...` 走 SSH（系统 ssh-agent 与 `~/.ssh/config`）。
- `https://...` 走系统的凭据管理；也可以把 token 存成本地文件（`sync-token`，0600）作为兜底，不会写进命令行或 git 配置。

## 自动同步

自动同步默认开启：启动时先拉取，内容有变化后约 30 秒自动推送；网络不通会自动重试，出现冲突时暂停自动同步。

## 安全模型

- **歌单与注释以明文托管**：私有仓库只提供访问控制，删除也不会抹掉 git 历史。
- **登录态会加密后再同步**，口令只留在你自己的设备上，新设备输入一次即可。
- 同一份内容在两端都改过才会冲突，冲突时逐项选择保留哪边。
- 登录态以最近一次登录为准，不弹冲突选择；在一台设备退出登录，不影响其他设备。
- 队列、下载文件、全局音量与全局补偿、自动响度均衡、音质、播放模式、鼠标偏好、`lyrics.toml` 这些跟着设备走，不参与同步；单曲音量补偿、歌词绑定与偏移属于单曲注释，会同步（本机绑定除外）。
- 同步需要系统安装 `git`。
- 同步登录态可能触发平台风控，失效时会回落到扫码登录。

同步是按间隔进行的，不追求毫秒级一致。想了解设计与安全细节，见 [docs/sync-design.md](../sync-design.md) 与 [ADR 0016](../adr/0016-git-sync.md)。

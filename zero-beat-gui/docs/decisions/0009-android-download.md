# ADR-0009：Android 下载保存完整媒体流

- 状态：接受；支持的容器范围待 P1 真机验证
- 日期：2026-11-16

## 背景

Android 离线播放是 v0.1 目标。现有 Go 下载器会在 HTTP 下载后执行外部 ffmpeg 重封装并写标签；公开 SDK 和 media_kit 都不能自动消除这一依赖。桌面可检测系统 ffmpeg，Android 需要自己的完成处理方式。

## 决策

- 在 Go 下载器内分离 HTTP 传输/续传、完成处理器、下载索引；由平台入口注入完成处理器。
- 桌面继续使用 ffmpeg；Android v0.1 保存经过检查的完整媒体资源，保留原容器和标签，不 exec 外部程序。
- 支持范围按实际容器与完整性确定，不按 codec 或文件名猜测。清单流、缺初始化段的碎片和未经验证的格式明确拒绝；支持矩阵在 P1 以 B 站、网易云真机下载和离线播放样本锁定。
- `.part` 校验完成并原子改名后才登记下载成功；续传校验资源身份，取消/失败不生成成功索引。曲名、艺人等显示元数据继续来自曲库。
- P1 验证原型，P3 交付任务管理、批量、取消/续传与分享；无法满足两音源的必需离线场景时重新评估方案和排期，不默认降级为“只有桌面能下载”。

## 后果

- Android 播放与下载都不要求系统 ffmpeg；桌面下载的行为保持原有封装/标签语义。
- Android 导出的媒体不保证带有新写入的标签；不支持的流需要清晰提示，不能保存为错误扩展名或声称成功。
- 核心需要传输与落盘边界重构，以及跨平台下载回归；这项工作计入 P1 原型和 P3 实现。

## 备选

- **嵌入 libav 或原生封装后端**：需要额外 ABI、打包、格式和许可证验证；完整流方案不能满足必需场景时再评估。
- **随包放 ffmpeg 可执行文件**：增加 Android 执行路径、打包和系统版本约束，v0.1 不采用。
- **禁用 Android 下载**：不符合现有离线播放目标；若采用必须更新目标、验收与路线图。

实现契约与验收见 [04-sync-and-data](../04-sync-and-data.md)。

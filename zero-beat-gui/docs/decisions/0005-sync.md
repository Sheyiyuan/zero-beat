# ADR-0005：数据与同步

- 状态：接受
- 日期：2026-11-16
- 修订：2026-11-16（补齐 v2 字节契约、合并祖先与写前校验）

## 背景

GUI 要和 TUI 共用数据：

- 桌面：同一数据目录、同一 SQLite（Windows 为 `%APPDATA%\zero-beat`）；
- 跨设备：同一 sync v2 git 仓库；
- Android：没有 `git` 二进制；
- Windows：不保证装有 Git for Windows。

同步仓库的难点不在「读」，而在「写出完全一致的字节」：确定性 JSON、Argon2id 参数、XChaCha20 密文、accounts LWW、`merge=binary` 的实体级冲突。任何一处不一致都会制造假冲突或解密失败。

## 决策

**SQLite 与 sync 仓库只由 Go 核心读写；Dart 只通过 RPC 使用数据。**

- SQLite：schema、迁移、WAL 参数与 TUI 完全一致；macOS 路径 `~/Library/Application Support/zero-beat`，Windows `%APPDATA%\zero-beat`；Android 路径由 Flutter 传入；
- sync：复用 zero-beat 的 `zero-beat-core/sync`，通过公开的 `sync` 门面暴露给 GUI；**不把 sync 代码复制进 GUI 仓库**；
- Git 后端做成接口，TUI 与 GUI 共用：
  - `auto`（默认）：Linux/macOS 优先可用 CLI，否则 go-git；Windows/Android 优先 go-git；
  - 强制：`ZERO_SYNC_BACKEND=cli|gogit` / `sync.toml` / `zero sync --backend`；
  - Android、Windows 默认 go-git；Linux/macOS 默认 CLI，缺失时自动回退；
  - 两种后端共用同一套快照、导入、冲突索引、加密与合并逻辑；
- 冲突读取后端中立：后端从固定提交 tree 返回 `base/local/remote` 三份字节及存在标记，不依赖 git index stage；CLI 也消费共享合并器结果；
- 合并以真实共同祖先为基准，区分相同头、快进、本地领先与分叉；分叉合并提交父节点必须为 `[localHead, remoteHead]`。删除/修改和不同内容的新增冲突不能遗漏；非空无关历史或多个最佳共同祖先明确拒绝，不能猜基准；
- 冲突选择绑定原始三头与库 revision，输入变化后重新计算；引用更新校验旧头，push 非快进重新 fetch/合并并有界重试。保存事务阶段支持恢复，不 force push；
- 仓库格式不新增字段；`meta.v` 必须是 2；`v>2` 拒绝写入；
- 同步文件沿用现有 Unix 秒/毫秒等字段类型，不使用 RPC 的 RFC3339 DTO。现有严格解析不支持未知字段透传；core 已加入写前校验，GUI 接入仍需验证未知字段/版本在覆盖、导入、提交前阻止写同步；
- 设备态（queue、下载、音量、模式、鼠标偏好、本地文件夹歌单、本地歌词绑定）不进仓库。

## 后果

- 以现有 v2 样本与双端回归锁定格式；TUI 与 GUI 交替同步需验证最终树、冲突结果与提交祖先。
- **生产 go-git 已前移至 TUI 阶段**：core 提供双后端；无 Git 双设备测试不借助系统 Git 准备仓库。GUI 后续复用，完整平台验收另行完成。
- macOS 关闭沙盒后，sync 目录与 TUI 共用 `~/Library/Application Support/zero-beat/sync`；git CLI 可用则优先，否则 go-git。
- 生产后端已前移至 TUI 阶段，GUI P5 仅计 1–2 人周的 RPC/配置/冲突 UI 接入；P1 独立原型先验证分叉合并和 Android HTTPS。明细与验收见 [04-sync-and-data](../04-sync-and-data.md)。
- Git 后端在整轮开始前探测并固定；仅 CLI 不可用时回退，认证/网络/冲突失败不能中途换后端继续同一事务。
- 不在 Dart 里做快照导出；冲突 UI 通过 RPC 展示，冲突文件格式与 TUI 兼容。
- 如果 zero-beat 的公开 SDK 迟迟不能落地，**也不要**把 `zero-beat-core/sync` 复制到 GUI 仓库作为临时兜底；临时方案只能是「GUI 只读同步」或延后同步，避免一个仓库两种格式。

## 备选

- **把 sync 合进 GUI 仓库（fork）**：被否。这是「兜底」里最危险的一种；序列化/加密/合并任何一处偏差都会破坏仓库。
- **Android/Windows 用 libgit2（cgo）**：保留为 go-git 不达标时的备选；构建更重。
- **Android/Windows 只读同步**：降级方案；能看不能改，体验不完整。
